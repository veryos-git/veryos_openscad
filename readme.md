# hgc 
stands for human generated content, do not edit text in files that have the hgc prefix or suffix

# publishing

Single source of truth for publishing material. If another file disagrees, this section wins. `listing.md`, `UPLOAD.txt` and `generation.*` in existing packs only record what was done then.

Goal: show the real print, and show that the OpenSCAD script makes it customizable.

## material

Everything goes in `<project>/publish/`. Numbered items are uploaded in this order.

| # | material | file | shows |
| --- | --- | --- | --- |
| 1 | thumbnail | `thumbnail_4x3.png` | real photo, both logos |
| 2 | photos | original photo files | the print from other angles, in use, details |
| 3 | variant overview | `images/01_<topic>.png` | different variations from one script |
| 4 | parameter images | `images/02_<parameter>.png`, `03_...` | the most important parameters, annotated |
| 5 | print layout | `images/NN_print.png` | parts on the bed, required hardware |
| 6 | portrait cover | `thumbnail_3x4.png` | same as the thumbnail, where a vertical image is needed |
| - | contact sheet | `contact-sheet.png` | all images in upload order, for review, not uploaded |
| - | listing text | `listing.md` | see [listing](#listing) |
| - | print files | see [print files](#print-files) | |
| - | build script | `source/build.py` | stages `--stage=mesh`, `render`, `compose`; `--draft` for quick checks |

## image format

| rule | value |
| --- | --- |
| generated images | compressed PNG, sRGB, no JPG |
| original photos | stay unchanged, uploaded as they are |
| landscape | 2400 × 1800 (4:3) |
| portrait | 1800 × 2400 (3:4) |
| renders vs photos | every image says which it shows: `PRINTED`, `CAD RENDERS`, `SAME SCALE`, `ILLUSTRATIVE COLORS` |

## thumbnail

Example: [V4 baby wipes box](projects/01_published_or_archived/babywipesboxV2/V4/publish/thumbnail_4x3.png).

| rule | value |
| --- | --- |
| main image | real photo of the printed model, not a render |
| no print yet | not published: print first, then photograph |
| version | the photo shows the version being published, not an earlier one |
| photo edits | crop, white balance and background only; the print is not retouched or regenerated |
| in the photo | no third-party brands |
| logos | VeryOS logo always, OpenSCAD logo if the project has a `.scad` file |
| text | short text that describes the product, readable at thumbnail size |
| variant strip | optional: small labelled renders of the variants beside the photo |

## brand

Source: [brand identity sheet](branding/identity/veryos-brand-identity.pdf). VeryOS stands for very open source: share everything, including the source.

| element | rule |
| --- | --- |
| headings, wordmark on images | DejaVu Sans Mono Bold |
| logo artwork in `branding/` | wordmark stays as drawn, in DejaVu Sans Bold |
| supporting text, labels, values | DejaVu Sans Mono |
| font license | Bitstream Vera: free to use, not CC0; keep its notice if font files are shared |
| slogan | `Very Open Source.` |
| backgrounds | Graphite `#151B1D`, Ivory `#F4EFE3`, Amber `#F1B84F` |
| accents | Gold `#F0B750`, Ochre `#B77B1E` on ivory, gradient `#FFCE76` → `#E7A43A` |
| VeryOS logo | rendered from `veryos_logo.svg`, never redrawn or generated; keep proportions and cutouts |
| logo clear space | ¼ of the symbol width; filled mark at small sizes |
| logo variants | `branding/logo/`: black/white, filled/outline, solid/transparent background, tight/padded (10 % of width), SVG + PNG; rebuilt by `build.py` |
| OpenSCAD logo | `projects/01_published_or_archived/fdm_optimized_screws/publish/source/assets/openscad.png` |
| lettering | typeset by the compose script, not generated by an image model |

## variant overview

Highlights that the script customizes the model. Example: [four sizes, one script](projects/01_published_or_archived/babywipesboxV2/V4/publish/images/01_four_sizes.png).

| rule | value |
| --- | --- |
| count | 4 by default, in one image |
| difference | visible at a glance, e.g. boxes: cubic, elongated, tall |
| sense | every variant is a practical product, no impractical dimensions just to look different |
| scale | same camera and scale for all variants |
| labels | variant name and its values, in mm |
| presets | every variant is a Customizer preset in `<scad name>.json` next to the `.scad` |
| not printed | digital examples, see [honesty](#honesty) |

## parameter images

Example: [wall angle](projects/cuboid_video_light_softbox/publish/images/03_wall_angle.png).

| rule | value |
| --- | --- |
| which | the parameters a user most likely changes: size, fit, look |
| layout | one image per parameter or related group |
| values | the default and clearly different values, same camera and scale |
| other parameters | stay at the default; a change that a constraint requires is labelled too |
| annotation | parameter name as in the script with its value, e.g. `wall_angle = 24` |
| explanation | one line on what it changes, plus any limit, e.g. `Keep wallcover_lip_clearance ≥ wallcover_thickness × tan(wall_angle)` |
| placement | dimension lines and labels projected from known geometry points, typeset after rendering |

## renders

| rule | value |
| --- | --- |
| geometry | exported with OpenSCAD from the project's `.scad`, parameter overrides only, source unchanged |
| look | rendered in Blender; colors are presentation only |
| cutaways, assemblies | explanatory only, not offered as printable parts |

## listing

`listing.md`, in this order. Example: [V4 listing](projects/01_published_or_archived/babywipesboxV2/V4/publish/listing.md).

| section | content |
| --- | --- |
| title | product, main feature, `Customizable` or `Parametric` |
| summary | 1–3 sentences, says it is parametric in OpenSCAD |
| description | how it works, customize table (parameter, default, options), presets table, files, printing, assembly, make your own size, status |
| tags | about 20, always `parametric`, `customizable`, `OpenSCAD`, `FDM`, `VeryOS` |
| files to upload | per site, see [print files](#print-files) |
| images | table of file and caption / alt text, in upload order |
| rebuild | commands that regenerate the images |

## print files

| file | rule |
| --- | --- |
| `.stl` | one per part, in print orientation |
| `.3mf` | settings of the photographed print |
| `.scad`, `.json` | source with dependencies, and its presets |
| license | GPL-2.0, see `LICENSE`; choose a GPL license where the site offers one |

| site | print profile | model files |
| --- | --- | --- |
| MakerWorld | Bambu `.3mf` | `.stl`, `.scad`, `.json` |
| Printables | none | `.stl`, all `.3mf`, `.scad`, `.json` |

## honesty

- The listing's status says what was printed and what is digital only.
- No claim of fit, print success or compatibility without a real print.
- Hardware and other parts that are not printed are named as separate items.

## checks before upload

| check | passes when |
| --- | --- |
| meshes | every exported mesh is closed, with positive volume |
| presets | every preset reproduces the pictured geometry |
| images | `contact-sheet.png` reviewed, in upload order |
| clearances | taken from `lessons_learned.md` |
